Fix and upgrade the volunteer certificate system in my SDG Synergy prototype.

CURRENT PROBLEM:
Right now, the volunteering certificate is being generated only for the NGO list that I manually added. That is not enough.

EXPECTED BEHAVIOR:
The volunteering certificate feature must work for:
1. NGO directory items that allow volunteering
2. Projects shown in the Projects Dashboard
3. Any project that requires help and has a volunteer/help submission form
4. Any completed volunteering/help submission where the project owner marks the contribution as completed

IMPORTANT RULE:
Do not tie certificate generation only to the NGO master list.
Instead, tie certificate generation to the submission/completion workflow.

NEW LOGIC TO IMPLEMENT:
- Any project that has a “requires help” or “volunteer needed” flow should collect volunteer/help form data.
- When a user applies through that project form, save the submitted details in the common submissions data model.
- If that submission is volunteering-related and gets marked as completed, the app should generate a certificate from that submission record.
- This must work whether the project came from:
  - NGO directory
  - project dashboard
  - dynamic project cards
  - future added projects

CERTIFICATE ELIGIBILITY LOGIC:
Create a reusable logic such as:
certificateEligible = true when:
- submissionType is volunteer / volunteering / field support / teaching support / event support / awareness campaign volunteer / cleanup volunteer / project execution support
AND
- status is completed
AND
- applicant name + project name + NGO name + start/end dates exist

If those conditions are satisfied, show:
- View Certificate
- Download Certificate

If not, do not show certificate actions.

ARCHITECTURE CHANGE:
Refactor certificate generation so it uses a shared data source like:
- helpSubmissions[]
or
- applications[]
and not a hardcoded NGO list.

Every certificate should be generated from the selected submission record.
